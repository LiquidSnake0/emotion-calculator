# Session studio du 26 septembre 2026 — le premier set réel

Un studio prêté pour enregistrer un mix. Le set se joue **sur clé USB rekordbox**, sur deux
CDJ et une **DJM-750MK2**. C'est la première fois que le moteur entend une vraie table, de
vrais faders, un vrai DJ qui enchaîne dix disques. Tout ce qui précède a été mesuré sur des
fondus fabriqués ; ce document dit ce qu'on teste, comment, et ce qu'on attend — **avant**
de le faire, pour ne pas se noter soi-même après coup.

Deux objectifs, dans cet ordre :

1. **Ramener la matière** : le WAV multipiste de la table, les images que le moteur a
   écrites (`.pak`), les notes du DJ. Si le direct rate, la matière suffit à tout rejouer.
2. **Voir le moteur en direct** sur un vrai set : capture, tempo, relais à chaque passage,
   cue qui change de voie, fenêtre qui suit le fader.

## Le montage

```
CDJ 1 ──► voie 1 ─┐                       USB (5 paires stéréo, 48 kHz, 24 bits)
CDJ 2 ──► voie 2 ─┤ DJM-750MK2 ═══════════════════════════════════════════════► portable
                  │   paire 1 = voie 1 avant fader   (« Control Tone »)          │
                  │   paire 2 = voie 2 avant fader                              │ parecord → WAV
                  │   paire 5 = Rec Out (master)                                │ moteur  → anneau → .pak
                  └─► salle                                                     │ fenêtre
```

Le casque ne passe pas par l'USB : **le cue du moteur est la voie avant fader du deck qui
se prépare**, et le moteur sait laquelle par l'alternance (`CueAlternant`, ci-dessous).
C'est plus propre que le casque, où le potard MIX laisse toujours passer du master.

Le portable est cette machine (HP EliteBook x360 1030 G3, Manjaro, noyau 6.1) : la
DJM-750MK2 y est connue du noyau (quirk ALSA depuis Linux 5.14), rien à installer. Il faut
un **câble USB-B**.

## Protocole, avant de jouer (10 minutes)

1. Brancher l'USB, lancer `./outils/studio.sh` : la carte DJM et sa source doivent
   apparaître, avec cinq paires et leurs commutateurs.
2. Mettre un disque sur chaque CDJ, en lecture, faders **en bas**. `./outils/studio.sh --verif` :
   choisit l'entrée de chaque voie à l'oreille (LINE / CD-LINE / DIGITAL / PHONO, les
   options que le noyau 6.1 expose pour ce modèle) et donne le niveau
   de chaque paire en dBFS. Attendu : paires 1 et 2 au-dessus de −40 dBFS, paire 5 à
   « rien » ou très bas (faders en bas), paires 3 et 4 à rien.
3. Monter le fader 1, relancer `--verif` : la paire 5 doit maintenant porter du signal.
4. `./outils/studio.sh set-studio <bpm du premier disque> [camelot]` : la fenêtre s'ouvre,
   le journal du moteur dit `cue alternant : voie 1 = djm_2, voie 2 = djm_1, le cue commence
   sur la 1` (ses « voies » sont les deux candidates, dans l'ordre donné). **Le premier
   disque joue sur la voie 1 de la table, le premier disque préparé est sur la voie 2.** Si
   le set commence dans l'autre sens, `STUDIO_CUE=1` ; et si on s'est trompé, le filet
   permute en trois secondes (une ligne `filet : …` dans le journal, c'est prévu).
5. Deuxième terminal : `./outils/terrain.sh set-studio`. **Le crate sur l'iPhone** : dans
   `~/Documents/crate`, `npm run dev -- --host 0.0.0.0`, puis sur le téléphone
   `http://<ip du portable>:5173/crate/` (l'ip est imprimée par `studio.sh`, c'est celle du
   partage de connexion ; en http, pas la PWA GitHub Pages qui est en https et ne peut pas
   appeler un moteur en http). Onglet **Set**, moteur = `http://<ip>:5099`, set = « Mix 2 »
   (importer `crate-mix2.json` dans Bibliothèque si ce navigateur ne l'a pas). Puis
   « démarrer », et à chaque disque « je le cale au casque » / « il passe en salle » : ce
   sont `/deck/play`, `/deck/cue`, `/deck/take`, journalisés côté moteur dans
   `<session>-deck.jsonl` à l'heure de la machine **et** à l'horloge des images. Plan B :
   `./outils/cue.sh set-studio …` à la main.
6. Vérifier que `<session>-table.wav` grossit (~1,4 Mo/s pour dix canaux) et que
   `<session>-pak.log` compte des images.
7. **Ne pas appuyer sur `Q` dans la fenêtre pendant le set** : la fenêtre est au premier
   plan du script, la fermer termine toute la session (moteur, `.pak`, WAV). On ferme à la
   fin, une fois, avec Ctrl-C dans le terminal ou `Q` — les deux arrêtent tout dans l'ordre.
   Le script inhibe la veille et le capot pendant la session (`systemd-inhibit`) ; le
   portable reste branché sur secteur. Les QR du crate et du JSON sont imprimés par
   `studio.sh` à l'adresse du moment, celle du partage de connexion.

## T0 — l'échauffement, avant le set

Deux ou trois disques du crate vinyle (ceux qui sont aussi sur la clé : *The Era of
Information* y est), joués à la suite, **avec l'écran Live du crate** — les probabilités,
pas l'ordre imposé. But : voir que la fiche arrive, que rien ne fuit d'un disque à l'autre,
avant de lancer le set. Gestes : choisir par quoi on démarre (`play`), taper la ligne du
candidat choisi (`cue`), « il passe en salle » quand le fader est en haut (`take`).

| vérifier | où | attendu |
|---|---|---|
| chaque geste répond 200 | ligne « moteur · … » sous le disque courant | 0 « injoignable » |
| le moteur a la bonne fiche | `curl <ip>:5099/deck` | `playing` = le disque en salle, `cued` = celui au casque, BPM = ancrage, Camelot = transposée |
| pas de fuite | `deck.jsonl` | une ligne par geste, dans l'ordre, chacune avec le bon titre |
| le relais suit | journal moteur | `cue → voie N` après chaque passage ; pas de « filet » après le premier |

Si T0 échoue sur le réseau (partage de connexion), on passe au plan B `cue.sh` et le set
se joue quand même.

## Ce qu'on ne saura pas demain

- Le relais en direct est testé avec un cue qui est **la voie brute**, pas le casque : ce que
  le DJ entend n'entre pas dans le moteur. Ce n'est pas un manque, c'est le montage.
- Le pitch et l'EQ sur un vrai fader ne se jugent qu'à la maison (T8).
- Les 15 fiches de Mix 2 ont BPM et Camelot (12 lus sur la clé, 3 donnés par le DJ depuis
  rekordbox) ; tout `cue` part avec sa clé.

## Résultats de la session du 26 septembre 2026 (écrits sur place, à 16 h)

### Ce que la table a imposé, avant la première note

- **Pas de quirk pour la 750MK2 sur ce noyau 6.1** (`Controls : 0`) : la table streame du
  silence tant que personne ne lui parle. `outils/djm_routage.py` envoie les requêtes USB
  vendeur du noyau (`SET_FEATURE`, `wValue = paire << 8 | source`, `wIndex 0x8002`), le
  nœud USB ouvert par `sudo chmod o+w`.
- **La capture ne vit que si un flux de sortie tourne vers la table** (retour implicite) :
  `pacat /dev/zero` permanent. Sans lui, douze canaux à zéro.
- **Les canaux, par les noms PulseAudio** : CH2 = rear-left/rear-right, CH3 =
  front-center/lfe, Rec Out = aux0/aux1. L'ordre brut trompe.
- **Les entrées avant fader (LINE, CD/LINE, PHONO) sont restées muettes** malgré le
  sélecteur sur LINE ; DIGITAL refusé par la table (`Pipe error`). Donc **voies après
  fader** pour le cue, Rec Out pour le master. À creuser : un autre code sur ce firmware.
